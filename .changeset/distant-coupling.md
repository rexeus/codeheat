Rank the places where structurally distant code keeps changing together, and add two scaling signals. `analyze --json` gains `distantCouplings` (coupled pairs in different modules, or far apart within one, without test code and pairs of two contract files, ranked by strength times module distance, hidden couplings higher), `moduleCoupling` (per pair of modules the shared counted commits and the share of the smaller module's commits, the data of a coupling matrix), `cliques` (groups of at least three modules of which every pair shares 30% of the smaller module's commits, each with a one-line reason), `unstableInterfaces` (TypeScript and JavaScript files many files import that change more often than their dependents, with the dependents that changed with them), and `dependencyDirection` (imports from a module that rarely changes to one that changes often, the Stable Dependencies Principle measured from change rates). `inspect` partners carry `distant`, `thresholds` report the new limits (`minLocalDistance`, `minCliqueShare`, `minFanIn`, `minInterfaceRevisions`, `minVolatilityRatio`), and `--limit` cuts the new lists like the others. The terminal shows the five best distant couplings and a line per clique ahead of the plain coupling table, marks distant partners in `inspect`, and lists the first unstable interfaces and stable-to-volatile imports. Dependencies for the two scaling signals are read as text from every non-test code file, which adds a few percent to the time of an analysis.
