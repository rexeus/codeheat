Include contract files in coupling: interface definitions and schemas (`.tsp`, `.proto`, `.graphql`, `.gql`, `.avsc`, `.thrift`, `.smithy`, `*.schema.json`, and `openapi.*`, `asyncapi.*`, `swagger.*` in YAML or JSON) now show which code follows them. They get no score, rank, or complexity and never appear in `files`, module sizes, leakage, or depth, but they couple with code, count as a touch of the module they live in for cohesion, and are marked `(contract)` in the terminal. A contract outside every module (a code-free `spec/` folder beside the packages) lives in that folder, and a module that changes with it lists it in `partners` with `contractsOnly: true` (`spec (contracts)` in the terminal), so a design-first package that loses cohesion to its contracts shows why.

`analyze --json` gains `contracts`, `totals.contracts`, `ubiquitousFiles`, `Coupling.kinds`, `Module.partners[].contractsOnly`, and the thresholds `ubiquitousShare` and `ubiquitousMinCommits`; `inspect` partners gain `kind` and the result gains `contractFiles`. `couplings` now lists pairs with a code side first and pairs of two contract files after them, so `--limit` keeps code pairs, and the terminal's coupling table leaves contract pairs out like test pairs. Commits that touch only contract files now count in `window.commits` and `window.couplingCommits`, which can move `minModuleCommits` and the denominators of module cohesion slightly. A contract file that changes in more than 30 % of the counted commits (a central schema every change touches) is listed in `ubiquitousFiles` and left out of every pair. `inspect api/orders.tsp` now says that it is a contract file and to inspect the code that changes with it (exit code 4 when nothing else matched). `.proto`, `.graphql`, and `.gql` are no longer scored as code, and `tsp-output/` joins the excluded output directories. `--exclude` removes contract files, `--include` replaces the contract list like the language list, and there is no new flag.
