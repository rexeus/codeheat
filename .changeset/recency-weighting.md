Weigh change by recency: recent work now counts more than the setup phase. Each commit weighs `0.5^(age / half-life)`, its age measured from the end of the window it falls in, so a commit at the end counts 1 and one a half-life earlier counts 0.5; a logical change weighs what its newest commit weighs. The new flag `--half-life <duration>` (`analyze` and `inspect`; `<n>d`, `<n>w`, `<n>m`, `<n>y`, or `0`) sets the half-life, 6 months by default; `0` weighs every change the same and restores the earlier numbers. An unreadable value exits with code 2.

`analyze --json` gains `FileStats.weightedRevisions` (a file's revisions at their weights, rounded to 4 decimals, or 4 significant digits below 0.1), `Module.weightedCommits` and `Module.weightedLocalCommits`, and `thresholds.halfLifeDays` (the half-life in days, 0 when weighting is off; `inspect --json` carries it as `halfLifeDays`). The hotspot `score` now follows `weightedRevisions`, a coupling's `degree` is the weight of the shared changes over the mean weighted changes of both files, and a module's `cohesion` is `weightedLocalCommits / weightedCommits`, both pulled towards their plain value by a prior worth three changes so that a few recent changes cannot collapse a ratio built on many old ones, so ranks, degrees, and cohesion of repositories with a long history change: setup-phase areas fall, recently active ones rise. `revisions`, `changes`, `sharedCommits`, `commits`, and `localCommits` stay plain counts, and so do the floors that gate pairs and modules (`minSharedCommits`, `minModuleCommits`, the hub floor), the co-change probability, the leakage, and the reason lines, so a pair is never dropped for being old alone. With `--compare`, each window is weighed from its own end. The terminal views name the half-life (`weighted by recency, half-life 6m` or `unweighted`) and show the weighted revisions next to the plain ones.
