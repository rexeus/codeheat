Mechanical commits no longer count as revisions, changed lines, or coupling, cohesion, and interface-churn evidence: exact renames and mode changes, whitespace-only diffs, a revert together with the commit it reverts (when both are in the window), commits whose patch id equals that of an older commit on a parallel line (cherry-picks, backports), and commits listed in `.git-blame-ignore-revs`. They still count in `window.commits` and still carry a file's history across renames. The report gains `mechanicalCommits`, a count per kind, plus `window.realCommits` and `comparison.previousRealCommits`, the commits that are not mechanical. A revert pairs with its original only when it undoes it exactly over the analyzed files (same paths, mirrored line counts, and each file either restored to the object it had before the original or changed by a patch equal to the original's reversed; lockfiles and other files outside the universe do not count); a patch applied again on top of an older copy (a re-land) counts as a real change. A re-indent is never whitespace-only where indentation is syntax (Python, Starlark, F#, Haskell, Scala, YAML, Makefiles, and similar). With `--compare`, a window without real commits has nothing to compare: file trends are `null`, and the terminal and the viewer say the window has only mechanical commits. Scores, couplings, and module cohesion of repositories with such commits change accordingly.
